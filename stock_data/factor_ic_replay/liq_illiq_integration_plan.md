## 一、证据摘要（为什么要专门讨论这两个因子）

| 因子 | 先验 | 验证集IC | ICIR | t | 分位单调ρ | TOP50超额 | 分年 IC（2023/24/25/26） |
|---|---|---|---|---|---|---|---|
| liq20★ | 多低 | −0.0955 | −0.541 | −5.11 | **−1.00** | **+140.5pp** | −0.143 / −0.056 / −0.094 / −0.086 |
| illiq20★ | 多高 | +0.0665 | +0.380 | +3.58 | **+0.99** | **+68.3pp** | +0.114 / +0.017 / +0.067 / +0.069 |

21 个存活因子里，**只有这两个**同时具备「IC 显著」与「TOP50 超额为正」；其余 19 个 IC 显著但组合为负（尾部毒性）。这就是必须单独决策的原因。

### 1.1 关键更正：这是**一个**暴露，不是两个 alpha

- liq20 与 illiq20 的 IC 几乎反向镜像（zoo 中 illiq 系列与 liq20 的 IC 相关 −0.86 ~ −0.89），
  且 liq20 的 TOP 分位（D10=低流动性）与 illiq20 的 D10（高非流动性）**指向同一批票**。
- 即：二者本质都是**小盘 / 流动性溢价**的两种度量（Amihud 非流动性与 log 成交额）。
- **结论：接入它们只能算获得 1 个自由度，不是 2 个。** 任何「两个因子分散化」的说法都不成立。

### 1.2 三重折扣（`factor_zoo.md` 已写明的 caveat，量级必须显式）

TOP50 +140.5pp 的虚高来自三处系统性乐观：

1. **微盘**：低成交额/高 Amihud 的票天然偏小市值，而小市值在 A 股长期有超额（且波动极端）。
2. **幸存者**：universe = 今天还活着的票（无历史 ST/退市名单）→ 已退市/被 ST 的那批负面样本整体缺失。
3. **不可交易流动性**：TOP50 里可能包含停牌、涨跌停锁死、日成交额极小的票——**回测里能成交，实盘不能**。

→ 因此**接入判据必须以「剔除不可交易尾部后的超额」为准**，而不是报告里的 +140.5pp。

## 二、三个方案（机制 / 改动面 / 风险）

| | A. 风险中性化维度 | B. 正交化合成 | C. 并入 factor_timing 因子池 |
|---|---|---|---|
| 做法 | 把 liq/illiq 作为**风险暴露**入 `risk_config.json`（组合对该暴露设上限/中性），**不选股** | 对 5 策略打分横截面回归掉 liq/illiq/vol 暴露，检验残差是否提升日内排序 | 把 liq20/illiq20 变成「每日选票集」，纳入 `factor_timing` 的信念 IC 打分（与其他因子同权竞争） |
| 改动面 | 小（配置 + 中性化层） | 中（新增研究脚本，先不改生产） | 大（factor_timing 现以「策略」为单位，需先把横截面因子转成每日选票集） |
| 预期 | 降低意外的小盘暴露，不指望增收 | 判断 liq/illiq 是否含**增量** alpha（而非重复已有策略） | 由 overlay 自动决定生效/权重（与现有生产接线一致） |
| 主要风险 | 可能与现有「行业/β/单名」中性化层冲突 | 若残差无改善 → 白做一轮（但有信息量） | **把小盘押注制度化**——正是三重折扣最集中的方向 |
| 前置条件 | 无（纯风控） | 需要干净的暴露估计 | 需要先定义 liq/illiq 的**选股规则**（top-N、剔除规则） |

### 2.1 对方案 C 的一个硬约束（容易被忽略）

`factor_timing` 的单元是「**策略**」：每天要给每个因子一个「选中票集合」，才能算信念 IC
（分配器权重 vs 该因子选中票前向收益的滚动 Spearman，见 `factor_timing.py`）。
liq20/illiq20 目前只是**横截面排序**，**没有**「选中票集」这个概念。所以 C 不是插上就用，
必须先定义规则，例如：

- 规则：`liq20` 取当日「最低流动性分位」前 N 名（注意 liq20 先验=多低 → **做多低流动性**）。
- 但请注意：**这个规则本身就是在买微盘股**，与 1.2 的三重折扣正面冲突。

→ 因此 **C 必须排在 A/B 之后**，且只有在「剔除不可交易尾部后超额仍显著为正」时才考虑。

## 三、推荐路径（分阶段，先诊断后落地）

### 阶段 0（诊断，**零生产改动**，先做这一步）

产出一个诊断脚本，回答三个问题：

1. **增量性**：liq/illiq 与现有 5 策略选票的重叠度是多少？若几乎不重叠，才算新信息。
2. **残差 alpha**：把 5 策略打分横截面回归掉 liq20/illiq20/vol20 暴露后，残差 IC 是否显著提升？
3. **可交易性折价**：在 TOP50 里逐条施加「可交易过滤」后，超额还剩多少——
   - 剔除 ST（需历史名单，见 §五 待办）
   - 剔除信号日/持有期停牌、涨跌停锁死（k_data 可判）
   - 剔除当日成交额 < 阈值（如 5000 万）的票
   - 剔除价格 < 5 元 / 最小市值分位
   → 报告「逐条剔除后的超额衰减曲线」：**这就是三重折扣的量级**。

**阶段 0 的通过线（预注册）**：施加全部可交易过滤后，TOP50 全期超额仍 **> 0**，且分年至少 3/4 为正。
不通过 → 直接终止（结论：liq/illiq 超额不可交易）。

### 三.1 阶段 0 实测结果（2026-09-16）—— ❌ 未通过，终止

- 脚本：`scripts/liq_illiq_phase0_diagnostic.py`；报告：`liq_illiq_phase0_diagnostic.md` / `.json`。
- 三问的答案：

| 问题 | 实测 |
|---|---|
| ① 增量性 | 与生产选票（DAL 89 天可对齐）**recall / precision 双零**；与动量条件域 Jaccard **0.0（liq20）/ 0.0013（illiq20）** ⇒ 不是「新信息」，而是**另一个宇宙** |
| ② 残差 alpha | liq20 ↔ illiq20 秩相关 **−0.91**（同一暴露）；liq20 对 vol20 残差化后 IC 由 **−0.082 → −0.046**（**近半是 vol20 的重复暴露**） |
| ③ 可交易性折价 | **liq20**：TOP50 在「20 日均成交额 ≥ 5000 万」**第一级**就被全数打空（**211/211 期，保留票中位 0/50**）⇒ 完全不可交易；**illiq20**：保留 3/50，全期超额 **+197.2pp → −53.0pp**，全部过滤后 **−61.2pp、分年 2/9 为正** |

- 判定：两者均**未过**预注册通过线（liq20 连超额都无法评估）。按本节规则**直接终止**。
- 结论：**报告里 liq20 +140.5pp / illiq20 +68.3pp 的 TOP50 超额，主要是「买不进」的票贡献的**
  —— §1.2 的「三重折扣」不是保守估计，而是足以吞掉全部超额的量级。
- 附带结论：liq20 的一半 IC 与 vol20 重合，进一步削弱「新增自由度」的假设（§1.1 已定：二者合计仅 1 个自由度）。

### 阶段 1（若阶段 0 通过）→ 走方案 A：风险中性化

- 在 `risk_config.json` 增加 `liquidity` 暴露上限（沿用现有四层中性化的写法与阈值风格，
  **禁 magic number**，全部可配置）。
- 目的不是增收，而是**防止组合意外累积小盘暴露**——这本身就有价值，且风险极低。
- 验收：中性化前后，组合的 liq/illiq 暴露分位差显著收敛；对现有 5 策略选股结果的影响可解释。

### 阶段 2（若阶段 1 通过且研究继续支持）→ 再议方案 C

- 只有在阶段 0 的「可交易超额」稳健、且阶段 1 落地后仍想主动暴露时才做。
- 落地时必须走下面的门控。

## 四、预注册门控（任一阶段落地前必过）

复用 `scripts/walk_forward_factor_timing.py` 的**双轨门控**语义（该框架已预注册、已有月度回滚 tripwire）：

| 判据 | 阈值 | 说明 |
|---|---|---|
| 主判据：累计 OOS 改进 | ≥ 2pp | 与 factor_timing 同口径 |
| **可交易豁免** | 施加 §3 阶段0 全部可交易过滤后仍成立 | **本方案专属**，不可省 |
| 换手率约束 | `avg_flip` ≤ 0.5 | 相邻信号日生效集合平均翻转比例 |
| 显著性 | 单侧 t ≥ `FACTOR_TIMING_T_CRIT`（1.31, α=0.10） | `n_trials=1`（固定规则非挖矿，免多重检验罚） |
| 稳定性 | 前后半段同号、分年 ≥ 3/4 同号 | |
| 跨 regime 稳健 | 趋势上行 + 下行防御**两段都**跑赢基准 | |
| 因果安全 | 第 d 天只用严格早于 d 的历史 | 与 `factor_timing` 同标准，须单测守护 |

**通过 → 才允许 `--apply` 写回配置；不通过一律维持关闭。**

## 五、回滚

- 挂**月度回滚 tripwire**（沿用现有自动化模式：每月 1 日 09:00 跑门控 `--enforce` 幂等写回）。
- 配置回滚必须幂等（可重复执行、结果一致）。

## 六、Caveats / 待办

- **无历史 ST 名单**：`factor_zoo` 与 v1 回放均未剔 ST。阶段 0 需要它才能真正剔除；
  当前只能用「名称含 ST」的现名单近似 → 必须标注为未完全解决。
- **无历史流通股本**：换手率用成交额代理，市值分位只能用价格 × 近似股本，
  微盘判定精度有限。
- **10 日持有 vs 策略实际周期**：本设计沿用 T+10 口径，落地前需确认与目标持有期一致。
- **不要重复计算同一暴露**：liq20/illiq20 = 1 个自由度（见 §1.1），任何文档/报告都不得
  把它们当两个独立因子加总。
